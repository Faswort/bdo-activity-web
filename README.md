# BDO-активность в браузере

**Открыть:** https://faswort.github.io/bdo-activity-web/

Веб-версия распознавания активности участников гильдии Black Desert Online:
загружаешь скриншоты со списком участников — получаешь готовый XLSX.

Работает целиком в браузере на GitHub Pages: сервера нет, изображения никуда не
отправляются, на выходе только файл таблицы.

## Что делает

1. Принимает до **14 скриншотов** за одну партию (одна партия — один день).
2. Находит на каждом кадре окно гильдии по заголовкам «Фамилия» и «Активность»,
   сам подстраивается под положение окна и разрешение экрана.
3. Читает фамилии и колонку активности (итог за неделю), склеивает повторы между
   кадрами, убирает дубликаты.
4. Скачивает один файл `BDO-активность_ДД-ММ-ГГГГ.xlsx` с листом
   «Активность по датам».

Столбец с датой называется по **дате загрузки** (`ДД-ММ-ГГГГ`). Файл гильдии
заранее не нужен: фамилии берутся так, как их прочитал OCR.

## Приватность и отсутствие следов

- Никакой отправки изображений на сервер: OCR выполняется через WebAssembly
  прямо на странице.
- Нет `localStorage`, `sessionStorage`, IndexedDB с данными гильдии, нет логов и
  сохранённых таблиц. После скачивания XLSX в браузере не остаётся ни
  скриншотов, ни результатов.
- Единственное, что кэширует браузер, — языковые модели Tesseract (~19 МБ),
  чтобы не скачивать их при каждом запуске. К данным гильдии они отношения не
  имеют.
- Каждый пользователь работает со своей гильдией в своём браузере; публичный
  репозиторий чужие данные не накапливает.

## Как пользоваться

1. Открой страницу (GitHub Pages).
2. Перетащи скриншоты окна гильдии с вкладкой списка участников — до 14 штук.
3. Нажми «Распознать». Первый запуск скачивает языковые модели, дальше они
   берутся из кэша.
4. Проверь предпросмотр и нажми «Скачать XLSX».

Скриншоты должны быть полными кадрами игры, где видна таблица участников с
заголовками «Фамилия» и «Активность». Обрезки и кадры без таблицы приложение
отклонит с понятным сообщением.

## Точность

- Колонка активности читается отдельной моделью (`eng`), с инверсией цветов,
  увеличением ×2.5 и цифровым whitelist. На тестовом наборе из 7 скриншотов это
  дало 118 из 118 верных значений.
- Имена читаются моделью `rus+eng` с повышением резкости; похожие варианты
  одного ника объединяются.
- Всё равно стоит просматривать предпросмотр: нестандартные шрифты, сильное
  сжатие JPEG или перекрытые подсказки могут испортить отдельные строки.
  Подозрительные места и объединения показываются в блоке «Замечания».

## Локальный запуск

Нужен Node.js 20+.

```bash
npm install --ignore-scripts
npm run dev
```

`predev`/`prebuild` запускают `scripts/assets.mjs`: он копирует в `public/`
воркер и wasm-ядро Tesseract из `node_modules` и скачивает языковые модели
`rus` и `eng`. Всё это лежит рядом со страницей, без CDN.

Сборка:

```bash
npm run build     # tsc --noEmit && vite build
npm run preview
```

`dist/` можно открыть любым статическим сервером. Просто открыть
`dist/index.html` двойным щелчком не получится: браузер блокирует WebAssembly и
модули на `file://`.

## Публикация на GitHub Pages

В репозитории уже есть `.github/workflows/deploy.yml`: каждый пуш в `main`
собирает проект и выкладывает `dist/` на GitHub Pages.

1. Создай репозиторий и запушь код.
2. В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
3. После первого успешного workflow страница будет доступна по адресу
   `https://<user>.github.io/<repo>/`.

`vite.config.ts` использует `base: './'`, поэтому сборка работает и в корне
домена, и в подпапке репозитория без пересборки.

## Структура

| Файл | Назначение |
| --- | --- |
| `src/main.ts` | интерфейс, состояние, прогресс, метрики |
| `src/layout.ts` | поиск заголовков и геометрия колонок |
| `src/extract.ts` | чтение строк одного скриншота |
| `src/ocr.ts` | воркеры Tesseract и режимы распознавания |
| `src/imaging.ts` | кадрирование, резкость, инверсия, масштаб |
| `src/merge.ts` | склейка повторов и похожих имён |
| `src/export.ts` | стилизованный XLSX через `xlsx-js-style` |
| `scripts/assets.mjs` | подготовка OCR-ресурсов в `public/` |

## Ограничения

- Одна партия — один день и не больше 14 изображений.
- Выгружается только итоговая активность; недельный прирост `(+N)` не входит в
  таблицу (используется лишь для проверки чтения).
- Ручная правка таблицы в приложении не предусмотрена: при ошибке убери
  проблемный кадр и запусти распознавание заново.
